# audiomass-dev

Operational knowledge for working on the AudioMass fork at `audiomass/` inside the Project-B workspace, plus its GPU demucs backend. This is the "gotchas" skill — the app is plain browser JS served directly from `src/`, and most mistakes here come from line endings, stale browser caches, or breaking the plugin contract.

## When to use

- Any edit to `audiomass/src/**` (frontend JS/CSS/HTML) or the AudioMass server.
- Work on htdemucs separation, the plugin registry, the BPM/key scanner, or the GPU warm pool.
- Debugging "my change doesn't show up" or "BPM is wrong" in AudioMass.

## Hard rules

1. **Line endings are PER-FILE, not all-CRLF.** The files we edit most — `engine.js`, `multitrack.js`, `ui.js`, `state.js`, `wav.js`, `drag.js`, `lame.js`, `oneup.js` — are CRLF in HEAD, but `tempo-estimator.js`, `tempo-worker.js`, `fx-pg-eq.js`, `ui-fx.js`, `markers.js`, `rnn_denoise.js`, `amss-format.js` and most others are LF, and a few are mixed (`keys.js`, `actions.js`, `app.js`, `modal.js`, `flac.js`). **Always check first**: `git show HEAD:src/<file> | grep -c $'\r$'` — 0 means LF, ~total means CRLF. Match the file's own convention with a byte-safe Python patch; never rewrite a whole file's endings or the diff explodes into line-ending noise (this bit us: the BPM fix rewrote LF `tempo-estimator.js` as CRLF, inflating its diff from 129 to 529 lines). Sanity-check `git diff --stat` after editing — inflated numbers mean ending churn.
2. **Bump the cache-buster or your change won't load.** `audiomass/src/index.html` references files with `?v=` suffixes (e.g. `multitrack.js?v=mt118`, `tempo-estimator.js?v=mt5`, `engine.js?v=mt31`, `tempo-worker.js?v=mt4`). After editing a file, bump its version string or the browser serves stale code. This has bitten us repeatedly (missing key badge, missing features).
3. **Syntax gate is `node --check <file>.js`.** No linter, no test suite for the frontend. Run `node --check` on every edited JS file. Host-side unit tests live in `tests/` and run with `node --test`.
4. **Edits are live without restart.** AudioMass serves directly from `src/` (no bundle step). Edit → bump cache-buster → hard-reload the browser. The server (launcher-managed, :5055) does not need a restart.
5. **Runtime verification belongs to the user.** The agent can verify DOM/canvas/console in the preview tab, but the user hears the audio. Say "user to verify in browser" for anything sonic.
6. **Undo in multitrack is `pushState ( prev, desc )`** — NOT `registerUndo` (that function does not exist anywhere in src/; the old eraser + silence actions called it and threw a silent ReferenceError after mutating — fixed to `pushState`). Always snapshot `var prev = cloneState ();` before mutating clips/tracks, then `pushState ( prev, 'Action Name' )` once.

7. **Don't break the plugin contract.** Every processing plugin (htdemucs, analyze, waveform, transcribe) registers a named capability with a uniform job/progress contract. Pipeline phases: per-phase progress spans, `CancelledError` → `mark_cancelled`, non-cancel errors → `mark_failed` with friendly message, and the `finally` block must always run `cancellation_service.clear()` + log-handler detach.
7. **Single-key shortcuts fire on `keypress`, not `keydown`.** `KeyHandler.addSingleCallback` (keys.js) dispatches on the `keypress` event; combos via `addCallback` fire on `keydown`. All keybindings live in `engine.js` (Space=32, `` ` ``=96, Q=113, M=109 add-marker, L=108 loop, [ ]=219/221 seek prev/next marker, Backspace=8 cut, Delete=46 cut, **Home=36 jump to song start** → `RequestSeekTo, 0`, **Ctrl+A=65 select-all in MultiTrack** → `app.multitrack.SelectAllClips()` selects every clip **and** marks every track lane (`all_tracks_sel`; exposed as `q.SelectAllTracks`/`q.DeselectAllTracks`/`q.AreAllTracksSelected`). While all tracks are selected, channel-strip ops broadcast to every track: `setTrackFlag` (M/S), volume & pan knob drags/resets (via `selectedTracks()`). Any click on a single row/clip/add/drop/reorder exits all-tracks mode (ops return to single-track). Falls back to region-select `RequestSelect` in the main editor — Shift+A still always region-selects, **`,`=188 / `.`=190 prev/next beat-grid line in MultiTrack** → `app.multitrack.JumpGrid(±1)` — snaps the playhead to `60/BPM` boundaries; needs clips in the timeline). Note non-character keys (Home/arrows) produce **no keypress** — bind them via `addCallback` (keydown), not `addSingleCallback`. To simulate a key in the preview you must dispatch **both** keydown and keypress (with `keyCode` defined via `Object.defineProperty`, since `KeyboardEvent` ignores it). **Edit-target guard is centralized in keys.js**: `isEditTarget` covers INPUT/TEXTAREA/SELECT + `contenteditable` (self or ancestor), and `q.keyDown` early-returns when one is focused — so no app shortcut (including upstream ones like Backspace-cut or Space-stop) fires while typing. This was added after Backspace fired Cut while renaming; don't add per-binding guards, rely on the central one.
8. **Start the server with an absolute path.** `audiomass/run.sh start` resolves its own dir with `cd "$(dirname "$0")"` internally, so a relative invocation (`./audiomass/run.sh`) breaks the inner `cd ./audiomass`. Use `/mnt/Pandora/Project-B/audiomass/run.sh start` (absolute), exactly like the launcher does. Detach with `setsid nohup env AUDIOMASS_PORT=5055 <abs>/run.sh start > log 2>&1 < /dev/null &` — plain nohup gets reaped when the command runner exits.
9. **Drive mount guard — check before assuming "everything broke".** The Pandora drive must be at `/mnt/Pandora` (every path here hardcodes it). After the Aug-2026 drive incident the mount moved to `/media/neocyan/Pandora` and everything silently stopped working; the fstab entry was restored. `check-pandora-mount.sh` (repo + installed root-fs copy at `/usr/local/bin/check-pandora-mount.sh`) exits 0 when healthy, and prints the exact fix when the drive is missing or mounted elsewhere. It's wired into `run-aether-with-audiomass.sh start|restart` and the nightly `demucs-gpu-check.service` (`ExecStartPre`). If work in this repo suddenly "can't find files" or docker's store looks empty (data-root `/mnt/Pandora/docker-lib`), run `/usr/local/bin/check-pandora-mount.sh` FIRST — the drive likely moved again. Keep the repo copy and `/usr/local/bin` copy in sync (`sudo install -m 755 check-pandora-mount.sh /usr/local/bin/`).
9. **Mixed-endings files need ending-tolerant patching.** In `actions.js` the `fadeCurve` block is LF while the rest of the file is CRLF — a CRLF-only pattern silently fails (pattern count 0). Write patch scripts that try `\r\n`-joined then `\n`-joined patterns per replacement, and make them **idempotent** (skip a pattern when the new text is already present) so re-running after a partial failure is safe. `app.js` is also mixed.
10. **Clip context-menu labels are resolved by option name, not index.** `mt_context.onOpen` (multitrack.js) walks `menu.options` and matches `name === 'Crossfade'` / `name === 'Fade Curve: Quadratic'` to update labels (`childNodes[i]` aligns 1:1 with `options[i]`, separators included). This replaced the old hardcoded `a[6]`/`a[15]` indices — `a[6]` used to overwrite "Slice → 8" with the Crossfade toggle label (upstream bug, now fixed) — so inserting or removing options no longer breaks labels. Also note the `'---'` separator must be added as `addOption ('---', fn, '---')` — passing `true` renders the literal string "true" in the menu. Verify live after touching the menu: open it and check every label.

## File map

- `audiomass/src/tempo-estimator.js` — BPM + key detection (see BPM scanner section below)
- `audiomass/src/tempo-worker.js` — worker wrapper for the estimator
- `audiomass/src/engine.js` — wavesurfer wiring; auto-BPM-scan on song load (worker-first, capped to first 180s, job-id guarded)
- `audiomass/src/multitrack.js` — MultiTrack editor; owns beat-grid state + the main-view BPM/key badge
- `audiomass/src/main.css` — styles incl. compact sidebar
- `audiomass/src/index.html` — cache-buster version strings live here
- `audiomass/` server — uvicorn Python app (see `audiomass/CLAUDE.md`); /api/diagnostics exposes engine availability + warm-pool state

## Quick BPM scan on load (long tracks)

- **The scan never waits for the full decode.** On load, `engine.js` fires `quickScanTempo()` in parallel with the wavesurfer load: it fetches the first ~180s as a small mono-22k WAV from the server, decodes that tiny buffer, and runs the same estimator worker — the toolbar badge appears in ~1s while a 1-hour track is still decoding in the background.
- **Server endpoint** `audiomass-server.py`: `GET /api/tempo-segment?file=<rel>` slices a server-side file (ffmpeg `-t 180 -ac 1 -ar 22050`), `POST /api/tempo-segment` accepts the raw first-8MB head of a local blob (ffmpeg tolerates the truncated MP3/WAV/FLAC head). Cached per (path, mtime) in `/tmp/am-tempo-cache`. Returns 4xx/5xx JSON → frontend falls back to the ready-time scan.
- **Job/flag semantics** (`engine.js`): `scheduleTempoEstimate(buffer, job)` is the shared worker path; `quickScanTempo` bumps `tempo_job` (stale results guarded out) and sets `tempo_done_fast`+`tempo_fast_name`; `autoDetectTempo` skips the full rescan only if the same file name already got a quick result (so project loads / name changes still rescan).
- **Load entry points wired**: `LoadSample`/`LoadURL` (GET path), `LoadArrayBuffer`/`LoadFile` (POST blob head). The badge still feeds only the main-view toolbar chip — MultiTrack BPM stays manual (decoupled by design).
- **Gotcha (bit us twice):** finding a function's closing brace with `rstrip()=='}'` FAILS — `'\t\t}'.rstrip()` is `'\t\t}'` (rstrip only strips trailing whitespace). Use `.strip()` or a depth counter.
## BPM/key scanner (tempo-estimator.js)

- **Algorithm**: autocorrelation + log-Gaussian prior centered at 120 BPM (Ellis-style tempo induction) so octave-ambiguous tracks resolve to the perceived beat. The old interval-histogram method caused 167-BPM misreads and must stay demoted to an ultra-conservative fallback (flat curve AND interval confidence > 0.5). Confidence comes from the prior-independent peak gap (UI gate: > 15).
- **Key detection** (Krumhansl-Schmuckler): the FFT **must zero the imaginary buffer between frames** — forgetting this silently corrupts every frame after the first and the detector returns `null` (reproduce in Node with a synthetic C-major buffer).
- **Validate against known tempos**: synthetic tracks at 60/90/128/140 BPM with offbeat ticks + the real sample. Never trust a single run; detection can legitimately vary between plausible values on reload.

## GPU demucs warm pool

- Image `rocm64_gfx803_demucs:2.4` (RX 580 / gfx803 / ROCm) in docker. First job pays ~35s container+python+model startup; warm reuse drops subsequent jobs to seconds (e.g. 78s → 3.3s wall on a 12s track).
- `check-demucs-gpu.sh` — one-command smoke: starts docker if down, verifies image, runs two back-to-back jobs, asserts model loaded once, then idle-eviction (10s window) and eviction=idle in diagnostics.
- Pool semantics: warm reuse across jobs, cancellation kills the worker (verify the process is gone — a cancelled job must not burn CPU), idle eviction releases the GPU after N minutes, job counts + last-job stats persist across server restarts.
- Nightly regression: systemd timer runs the check; docker enabled at boot so the net actually runs.

## UI layout

- **Main editor** = viewing/playback + metadata. On load the BPM scan runs automatically and the result shows as a badge **inside the top toolbar** (`updateBpmBadge` in multitrack.js: appends an inline-block gold chip to `.pk_tb`, 13px/600 — it must NOT go over the waveform; the user rejected an overlay that covered the timeline). Two-chip layout: a name chip (max 220px, ellipsis, `title` hover shows the full name) + a BPM/key chip that NEVER truncates — so a long file name can't push the tempo info out of view. Text: name chip + `♪ {bpm} BPM · {key} · auto` — the file name comes from `app.engine.file_name` (engine.js captures it in `LoadSample` → `'test.mp3'`, `LoadFile` → `e.files[0].name`, `LoadArrayBuffer` → `e.name`; capped at 240px with ellipsis). The badge is **hidden while MultiTrack is on** (`updateBpmBadge` early-returns on `.pk_mt_on`; `Toggle` calls it so it returns when switching back). **No grid in the main editor — ever** (grid renders only inside MultiTrack's timeline).
- **MultiTrack** = editing. Right-side channel strip is compact by default (57px); right-click expands to full (179px) view.
- Beat grid (MultiTrack) uses the toolbar BPM field; detection feeds the main-view badge ONLY (`q.ApplyDetectedBpm` sets `badge_bpm`/`bpm_auto` — it must never write `beat_bpm`/the MT BPM field). MultiTrack BPM is manual (user edits it, then grid + snap follow). User's rule: "multitrack stays like previous — it cannot use scan bpm, it only can apply BPM on it edit and snap on it."
- **Pencil mode** (`✎` button next to the eraser in the MT extras tab, mutually exclusive with eraser): click deletes the clip(s) under the cursor on the current track; drag erases the covered range (clips removed / trimmed / split via `splitClipAt`); both are **clamped to the loop/selection region** (`region.start/end`) when one exists, and stacked/overlapping clips are all affected. Entry points: `bindClipDrag` mousedown + lane mousedown (both check `mt_pencil_mode`); erase logic in `pencilEraseClick`/`pencilErase`; drag highlight `.pk_mt_pencil_ov`.
- **Fade curves: per-clip type `clip.ftype` = `'quad'` (default, unchanged) or `'lin'`.** Threaded through: playback gain (`fadeGainAt` passes `clip.ftype` to `app.fadeGain(p, type)`), the drawn overlay (`fadeCurvePath` samples `fadeGain(p, clip.ftype)` — 8 segments), and the **destructive** Fade In/Out FX (`applyFx` passes `clip.ftype` as `fx_val` → `FXBank.FadeIn(val)` → `fadeCurve(rev, val)` in actions.js). Toggled via the clip context menu **"Fade Curve: …"** option, which flips the context clip + all multi-selected clips, pushes one undo state, re-renders, and updates its label. Serialized in both clip mappers (`ftype: c.ftype === 'lin' ? 'lin' : 'quad'`). New/old clips default to `'quad'` (undefined treated as quad everywhere).
- **Glass waveform clips (MultiTrack).** The clip is translucent so the beat grid shows through: `drawWave` uses an **alpha canvas** (`{alpha:true}` + `clearRect`, no opaque bg fill — peaks stay solid `tone[1]`), and the clip element's background is `var(--mt-bg-a)` = `hexA(tc[0], 0.5)` (hex→rgba helper set inline next to `--mt-bg` in the clip builder). Change `0.5` in that `setProperty` call to tune transparency. The recording-preview clip (`drawRecWave`) intentionally keeps its opaque fill. Grid paint order: `.pk_mt_beatgrid` (z-index:1) renders **above** `.pk_mt_lanes` (position:relative, z-index auto) — the grid was already on top; glass makes the waveform stop hiding it.

## Workflow for a typical edit

1. `node --check` the target file before editing to confirm baseline.
2. Edit with CRLF-preserving tooling (Python script; see hard rules).
3. `node --check` again; bump cache-busters in `index.html`.
4. Verify in the preview tab (AudioMass at `http://localhost:5055/` — load sample, check DOM/canvas/console).
5. Report to the user; state anything sonic as "user to verify in browser".
6. On request, commit to the audiomass fork (`audiomass-aegis` remote) or the Aether repo (`project-b-aether`).
